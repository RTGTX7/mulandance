# Blog Backend Plan: Mulan Dance Studio News/Updates System

## Overview

Build a file-based blog CMS backend with a Typecho-inspired Markdown editor UI, storing articles as `.md` files on disk while using the existing PostgreSQL database for admin authentication. This replaces the current database-backed `news_articles` content model with a hybrid architecture.

## Current Architecture

- **Backend**: FastAPI (Python 3.12), SQLAlchemy ORM, asyncpg, PostgreSQL 16
- **Frontend**: Next.js 14 (App Router), React 18, Tailwind CSS, shadcn/ui Radix primitives, Zod validation, next-intl for i18n
- **Auth**: JWT tokens (python-jose), bcrypt password hashing (passlib), `users` table with role-based access
- **Existing content API**: `GET /api/v1/content/news` returns from `news_articles` PostgreSQL table
- **Frontend NewsGrid**: Hardcoded local `articles[]` array, no API integration yet
- **Deploy**: Docker Compose (nginx + nextjs + fastapi + postgres)

## Design Decisions

### 1. Hybrid Architecture (Recommended)
Keep the existing `news_articles` Postgres table for metadata (slug, title, summary, cover_image, is_published, author_id, published_at) while storing the actual Markdown body in `.md` files on disk. This gives us:
- Fast metadata querying/searching via Postgres indexes
- Markdown flexibility via file storage
- No breaking changes to existing frontend pages or Alembic migrations
- Ability to serve both old DB articles and new file-based articles

### 2. File Structure
```
backend/
  data/
    news/
      2026-05-25-summer-showcase-announced.md
      2026-05-15-new-chinese-dance-class.md
      2026-04-20-winter-recap.md
```
- `data/news/` is created at startup if it doesn't exist
- Filenames follow `{YYYY-MM-DD}-{slug}.md` pattern
- Frontmatter (YAML) at the top of each `.md` file carries metadata

### 3. Markdown File Format
```markdown
---
title: "Summer Showcase 2026"
slug: "summer-showcase-announced"
summary: "Annual showcase details"
cover_image: "/images/showcase-2026.jpg"
category_slug: "summer-showcase"
locale: "en"
---

## The Big Night

Content in Markdown with full formatting support...
```

### 4. Category & Tag Database Schema
Dedicated tables for categories and tags with article-category/tag junction tables:

```sql
-- Categories (e.g., events, announcements, performances)
CREATE TABLE news_categories (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    slug VARCHAR(100) UNIQUE NOT NULL,
    name VARCHAR(100) NOT NULL,
    name_zh VARCHAR(100),
    description TEXT,
    color VARCHAR(7) DEFAULT '#6366f1', -- display color for filter badges
    is_active BOOLEAN DEFAULT TRUE,
    created_at TIMESTAMPTZ DEFAULT NOW()
);

-- Tags (free-form)
CREATE TABLE news_tags (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    slug VARCHAR(100) UNIQUE NOT NULL,
    name VARCHAR(100) NOT NULL,
    name_zh VARCHAR(100),
    created_at TIMESTAMPTZ DEFAULT NOW()
);

-- Article-Category junction (many-to-many)
CREATE TABLE news_article_categories (
    article_id UUID NOT NULL REFERENCES news_articles(id) ON DELETE CASCADE,
    category_id UUID NOT NULL REFERENCES news_categories(id) ON DELETE CASCADE,
    PRIMARY KEY (article_id, category_id)
);

-- Article-Tag junction (many-to-many)
CREATE TABLE news_article_tags (
    article_id UUID NOT NULL REFERENCES news_articles(id) ON DELETE CASCADE,
    tag_id UUID NOT NULL REFERENCES news_tags(id) ON DELETE CASCADE,
    PRIMARY KEY (article_id, tag_id)
);
```

Seeded initial data:
- Categories: `announcements` (公告), `performances` (演出), `classes` (课程), `studio` (工作室), `general` (综合)
- Tags: created per-article via the editor, not pre-seeded

### 5. Frontend Admin Dashboard
A `/admin` route group under the Next.js app (i18n-aware with `[locale]` prefix):
```
frontend/src/app/[locale]/admin/
  layout.tsx              # Auth-gated layout with locale routing
  login/

  dashboard/
    page.tsx              # Overview/stats
  editor/
    page.tsx              # Create/Editor (Typecho-inspired)
    [slug]/
      page.tsx            # Edit existing
  articles/
    page.tsx              # Article listing management
  categories/
    page.tsx              # Category management (CRUD)
  tags/
    page.tsx              # Tag management (CRUD)
```

```python
def require_admin_or_faculty(db: Session, user_id: str) -> User:
    user = db.query(User).filter(User.id == user_id).first()
    if not user or not user.is_active:
        raise HTTPException(401, "Invalid credentials")
    if user.role not in ("admin", "faculty"):
        raise HTTPException(403, "Insufficient permissions")
    return user
```

## Sequence: Create Article Flow

```
1. Admin types in Markdown editor (editor/page.tsx)
2. Frontend POSTs {title, slug, summary, body(md), cover_image, category_slugs, tag_slugs, locale, is_published}
   to API at POST /api/v1/news
3. Backend validates JWT + admin/editor role
4. Backend writes .md file with frontmatter to data/news/YYYY-MM-DD-slug.md
5. Backend creates news_articles record in Postgres (metadata only)
6. Backend inserts rows into news_article_categories + news_article_tags junction tables
7. Backend returns article JSON to frontend
8. Frontend shows success toast, redirects to dashboard/editor
```

## Sequence: Fetch Articles Flow (Public)

```
1. Frontend NewsGrid calls GET /api/v1/news?limit=6
2. Backend queries Postgres: news_articles AS a
   JOIN news_article_categories nac ON a.id = nac.article_id
   JOIN news_categories nc ON nac.category_id = nc.id
   WHERE a.is_published = true
3. Returns articles with category names, tags, and rendered HTML body
4. Frontend renders card grid
```

## Sequence: Fetch Article Detail

```
1. Frontend/SSR calls GET /api/v1/news/{slug}
2. Backend finds article in Postgres + data/news/ file
3. Reads .md file body and renders via mistune
4. Returns full article JSON with rendered HTML, categories, tags
5. Frontend renders article page with markdown content
```

## Security Considerations

1. **Password hashing**: Already using bcrypt via passlib (production-grade)
2. **Admin access**: JWT required, role checked on every write endpoint
3. **Markdown rendering**: Server-side HTML sanitization via `mistune` (safe by default)
4. **File permissions**: `data/` directory created with restricted permissions in Docker
5. **XSS prevention**: `mistune` produces clean HTML; client-side `marked` + `sanitize-html` for preview
6. **Rate limiting**: Nginx-level rate limiting (10 req/min) on `/api/v1/news` write endpoints
7. **Token expiry**: 30-minute access tokens, 7-day refresh tokens (existing config)
8. **CSRF protection**: `next-intl` middleware + SameSite cookie attributes
9. **Content validation**: Zod schemas on frontend, Pydantic v2 models on backend
