# Debug Plan: FastAPI 404 Errors

## Root Cause

The `backend/app/main.py` file got corrupted with **25 duplicate `catch_all` routes** (502 lines) from repeated failed edit attempts during a previous session. This catch-all route actively returns `{"detail": "API endpoint not found..."}` for every non-API request hitting port 8000.

The 404 requests originate from:
1. Chrome DevTools auto-requests (e.g., `/.well-known/appspecific/com.chrome.devtools.json`)
2. Background connection probes from the browser
3. Any client hitting port 8000 on a path that isn't an API route

## Plan

### Step 1 — Fix `backend/app/main.py` (rewrite cleanly)
- Remove all 25 duplicate `catch_all` routes
- Return to a clean file with only:
  - FastAPI app setup with CORS + API router
  - `/health` endpoint
  - Optional: `/docs` and `/redoc` (already configured in app init)
- Do NOT add a catch-all — let FastAPI return its default 404 behavior for unhandled paths

### Step 2 — Restart both servers
- Stop the running Next.js dev server (port 3000) and restart it
- Stop the running FastAPI server (port 8000) and restart it

### Step 3 — Verify
- `http://localhost:3000/en` — Frontend should load normally
- `http://localhost:8000/health` — Returns `{"status":"ok","service":"dance-org-api"}`
- `http://localhost:8000/docs` — Returns FastAPI auto-generated API docs
- `http://localhost:8000/` — FastAPI default 404 (not the custom catch-all)
- `http://localhost:8000/nonexistent-path` — FastAPI default 404 (not the custom catch-all)
