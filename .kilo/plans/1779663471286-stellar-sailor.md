# Plan: Fix Blank Admin Login Page

## Root Cause Analysis

The admin login page at `/en/admin/login` is displaying blank due to **two issues** in the Next.js build/internationalization setup:

### Issue 1: Duplicate `i18n.ts` files
- **`src/i18n.ts`** — references `getRequestConfig` from `next-intl/server` and uses `import()` to load locale JSON files
- **`src/lib/i18n.ts`** — same purpose, slightly different implementation
- **`next.config.js`** references `./src/i18n.ts` (without `/lib` prefix)
- Having two i18n config files can cause Next.js build-time confusion and `next-intl` plugin resolution errors

### Issue 2: `next.config.js` points to wrong path (potential)
- `createNextIntlPlugin('./src/i18n.ts')` — The plugin path should match the *middleware file*, not the i18n config file
- The middleware is at `middleware.ts` (in `frontend/` root), but `createNextIntlPlugin` should point to the middleware file, not an i18n config
- However, the custom i18n approach (LocaleProvider + useTranslations) in this project does NOT use `next-intl`'s built-in locale routing — the middleware already handles it with `createMiddleware`
- This means `next-intl/plugin` may be unnecessarily wrapping the Next.js config, and the custom LocaleProvider setup in `layout.tsx` handles messages directly

### Issue 3: Middleware matcher may skip admin routes
- Current matcher: `['/((?!api|_next/static|_next/image|*.{png,jpg,jpeg,gif,webp,svg}|favicon.ico).*)']`
- This pattern uses `*.{png,...}` as a negation prefix in the regex, which is **not valid** — `*` doesn't work as a wildcard prefix in regex character class negation
- Should be `(png|jpg|...)` instead of `*.{png,...}`

## Fix Plan

### Step 1: Remove duplicate `src/lib/i18n.ts`
The file at `src/lib/i18n.ts` is unused (it's not imported anywhere — the custom `i18n-client.tsx` handles runtime i18n, and `src/i18n.ts` is only used by `next-intl/plugin`). Delete this redundant file.

**Command:** Delete `frontend/src/lib/i18n.ts`

### Step 2: Fix `next.config.js` plugin path
The `createNextIntlPlugin` should reference the middleware file, not an i18n config file.

**Current (line 3):**
```javascript
const withNextIntl = createNextIntlPlugin('./src/i18n.ts');
```

**Fixed:**
```javascript
const withNextIntl = createNextIntlPlugin('./middleware.ts');
```

### Step 3: Fix middleware matcher regex
The negation pattern `*.{png,...}` is invalid. Replace with proper alternation.

**Current matcher (middleware.ts line 11):**
```javascript
matcher: ['/((?!api|_next/static|_next/image|*.{png,jpg,jpeg,gif,webp,svg}|favicon.ico).*)']
```

**Fixed:**
```javascript
matcher: ['/((?!api|_next/static|_next/image|.*\.(png|jpg|jpeg|gif|webp|svg)|favicon.ico).*)']
```

### Step 4: Restart dev server
Run `npm run dev` to pick up the changes and verify the admin login page renders correctly.
